# MCP Events callback egress research

OpenAI's [MCP Events specification](https://developers.openai.com/plugins/build/mcp-events) requires validating callback addresses at connection time and connecting to a validated address while preserving the hostname for TLS. DNS validation followed by an ordinary hostname-based `fetch` does not pin the connection: DNS may change between validation and connection.

Cloudflare's [TCP socket documentation](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/) says outbound sockets to Cloudflare IP ranges are blocked. Thus a socket pinned to a Cloudflare-fronted callback is not a general solution. The workerd [socket type definitions](https://github.com/cloudflare/workerd/blob/main/src/cloudflare/internal/sockets.d.ts) expose `startTls({ expectedServerHostname })`, but an [open production-edge report](https://github.com/cloudflare/workerd/issues/6903) says this option does not send SNI there; this is a report, not a verified platform guarantee. Test against the production edge before relying on this path.

Cloudflare documents that [`resolveOverride` only works when both hostnames are in the Worker's zone](https://developers.cloudflare.com/workers/runtime-apis/request/), so it cannot pin arbitrary callback hosts. The same documentation says Workers do not implement `redirect: "error"`; use `redirect: "manual"` and reject 3xx. Cloudflare also [documents](https://developers.cloudflare.com/workers/platform/known-issues/) restrictions on fetching IP-literal URLs. A DNS-validated hostname fetch remains vulnerable to rebinding between validation and connection; network-level restrictions are defense in depth, not a substitute for pinning.

True pinning for arbitrary Cloudflare-fronted callbacks requires a different egress path under these documented socket restrictions. One option is a small VPS or Fly Machine acting as an authenticated egress proxy, resolving and validating every address itself, connecting to the validated IP with the original hostname for TLS, and refusing redirects. [Fly's published pricing](https://fly.io/pricing/) lists a small shared 256 MB machine around $2.19/month for compute; network, IP, and other charges can add to that. No external service has been created.
